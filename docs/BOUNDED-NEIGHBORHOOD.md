# Bounded neighborhood retrieval

This experimental change addresses candidate losses recorded in the [adversarial review](reviews/JUDGING-RETRIEVAL-ADVERSARIAL-20261006.md). Its frozen native build passed 3,887 checks and strict signature verification. The matched repeat recovered no additional annotated positive turns and locally accepted hybrid 8/14 versus 10/14. It did not earn promotion. The working-tree ordinary default is restored to exact v1/16, with a fresh gated build still required. See [the architecture reassessment](reviews/ARCHITECTURE-REASSESSMENT-20261006.md).

## Selection contract

Explicit experimental selected-Qwen episodes use the exact `selected-model-context-components-v2` allocation. Ordinary episodes default to v1. Retrieval still produces at most 16 primary candidates. Every validated unique primary span appears before optional neighbors. Each original primary may contribute its immediate previous and next opposite-role messages, yielding at most 48 assembled spans; the upstream search windows are unchanged. Neighbor-only results never recursively expand. Consecutive same-role messages stop adjacency; conversation, project, source frontier and recent/current-request exclusions remain enforced.

The expansion version is `bounded-bidirectional-neighborhood-v1`. Metadata lookups and scalar-safe source pages use the original episode lease. Each neighbor prefix is at most 4,096 bytes. Repeated funded prefixes can be reused; a primary tail and a neighbor prefix from the same event remain distinct spans. The assembler verifies delivered payload against original source bytes through its funded read path. No question annotation or expected answer enters retrieval.

The total evidence byte and token allowances remain 131,072 bytes and 12,000 provider tokens. Primary protection applies to exact spans. Evidence component and whole-envelope reductions remove optional neighbors first, using geometric suffix reductions; when no neighbors remain, primaries may also be reduced to satisfy the actual limit. A retained primary is not a guarantee of full-message delivery or semantic relevance.

## Delivery and frozen evidence

The `bounded-neighborhood-provenance-v1` record binds each delivered event ID, original byte range, excerpt digest, candidate rank, origin and primary rank. Neighbors additionally bind their anchor and direction. The authoritative selection work retains the complete bounded provenance, initial candidate/assembly trace and actual delivery trace. The small delivery audit binds their digests and the selection work ID. If optional full traces cannot fit, it uses explicit `metadata_limit` omission markers; required source-range records remain present.

The delivery audit keeps its 32,768-byte ceiling. Forty-eight dated records can exceed that ceiling before a component proof is added. The new fitting step sizes the actual component proof and the UUID that will become the durable selection work ID. It removes the minimum suffix spans needed for the measured candidate to fit, neighbors before primaries. Changed evidence clears the old proof and work ID, then evidence and whole prompt are counted again under the original lease. Previous count charges remain. The actual replacement proof is checked again before selection work is frozen.

Audit-size exclusions and rounds have separate counters; `audit_size` identifies that reduction. Journal validation reconciles initial included spans with delivered spans and token, envelope and audit-size exclusions. Present bound traces must be dictionaries; arrays, numbers, strings and null cannot pass by supplying their digests.

Default and historical `selected-model-context-components-v1` episodes retain their exact 16-span contract, reduction version and JSON representation. The new optional counters remain absent in v1 records. The new binary verified and restored six genuine archives produced by the retained older binary. Independent SQLite comparisons preserved exact source payloads and dates, request bodies and admissions, frozen limits and origins, work evidence and resource totals.
