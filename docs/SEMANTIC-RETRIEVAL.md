# Local semantic retrieval

Status: native Send, foreground/read accounting and schema-5 background enforcement are integrated and pushed at `b006b6a`, October 5, 2026. Integrated verification is recorded in [STATUS.md](STATUS.md). This component supplies a source-backed semantic path for the read-only baseline. The optional summary tree remains gated by evaluation.

**Decision, October 8, 2026 (implemented):** by user decision, ordinary Send no longer uses this component, and the application no longer indexes in the background. Both are controlled by `SemanticRetrievalPolicy.ordinarySend`. The reason is measured: fused retrieval lowered delivered recall against lexical selection alone; see [the step 4 record](P2-SEMANTIC-DECISION.md#decision). The component, its contracts and the sidecar format are unchanged. Explicit evaluation and harness paths still build and query an index on demand. Existing sidecar files stay on disk unused. Statements below about Send and background triggers describe the component's behavior when the policy permits it.

## Adapter decision

The first adapter uses the installed macOS NaturalLanguage English sentence embedding, pinned to revision 1. On the development Mac, `NLEmbedding.supportedSentenceEmbeddingRevisions(for: .english)` includes revision 1; the requested embedding is available and produces 512-dimensional vectors for synthetic English sentences. The application does not request asset downloads or start an embedding server. If that exact revision is unavailable, semantic coverage is unavailable and original-source retrieval continues.

Apple exposes an explicit [sentence embedding revision](https://developer.apple.com/documentation/naturallanguage/nlembedding/sentenceembedding(for:revision:)), its [current revision](https://developer.apple.com/documentation/naturallanguage/nlembedding/currentsentenceembeddingrevision(for:)), and [string vectors](https://developer.apple.com/documentation/naturallanguage/nlembedding/vector(for:)). The adapter records provider, language, pinned revision, dimension, OS version/build, input-guard version, normalization version, and the digest of normalized vectors from fixed public probes. Apple does not expose a model-weight digest through this API. The fingerprint detects these observable changes; it cannot establish bitwise identity of unexposed assets across machines.

The API also exposes no verified tokenizer or model input-token usage. Each performed metered query encoding records one model call, its exact encoder input byte count and an unknown input-token operation. Development mode permits this explicit uncertainty. Strict known-input mode skips that encoder and reports lexical fallback. Vector dimensions or source character counts do not establish an input-token bound. Startup probes and indexing attempts consume the separate [durable background allowance](BACKGROUND-INDEX-BUDGET.md). Its six global resource caps enforce calls and declared bytes while retaining explicit unknown encoder input tokens.

The configured mlx-serve instance also returned 2,560-dimensional vectors for a synthetic request to `/v1/embeddings` naming the Qwen chat model. That observation does not identify a trained retrieval encoder or its pooling configuration. [mlx-serve's API documentation](https://github.com/ddalcu/mlx-serve/blob/main/docs/api.md) describes embeddings for BERT, EmbeddingGemma, and models such as Qwen3-Embedding. Boros will not adopt chat-model hidden-state output as its retrieval adapter without separate provenance and evaluation.

## Source and job contracts

Accepted events remain authoritative in `MemoryStore`. A semantic sidecar lives beneath the same private store directory and holds a strong reference to the owner store. It stores derived vectors, exact UTF-8 ranges, source IDs/digests, fingerprints, and content-free job state. It does not store a second copy of source text. The store supplies bounded project-scoped source manifests containing the monotonic sequence, event/conversation/project IDs, role, capture status, timestamp, digest, and accepted byte count.

Jobs are identified by index fingerprint and event ID. Their immutable input snapshot includes the complete canonical source reference: sequence, scope, role, capture status, original timestamp, digest and total bytes. A serial background worker reads bounded source ranges, computes at most a bounded number of chunks per work slice, and atomically publishes each chunk with the durable continuation offset. A restart retains the committed cursor and recovers interrupted jobs to pending without source-job inference. An explicit later trigger resumes with a new charged attempt; an interrupted calculation cannot make its chunk count as indexed. Unsupported ranges are retained as explicit holes rather than silently advancing a successful coverage watermark. Failed jobs retain a content-free reason and bounded retry state.

Computed prefixes remain unavailable to vector ranking until a final streaming read verifies the complete original SHA-256 digest. Completion seals the source at a durable publication sequence. A search frozen before that seal cannot acquire its newly eligible vectors afterward. Exact delivered excerpts also require their own stored range digest to match the original bytes. Failed jobs are excluded from vector ranking.

Source text is divided deterministically into bounded UTF-8 chunks, preferring the last whitespace boundary in a chunk's latter half. Separators remain in the recorded ranges, so the ranges partition the complete accepted source, including multibyte text. Every chunk retains the event digest, starting byte offset, and accepted byte length. The adapter conservatively rejects code-like text, non-ASCII letters, sentence-level non-English detection, and English confidence below 0.90. Language detection is a heuristic; a detector accepting a string does not prove that every word is English or that the embedding is useful for the task. The guard can reject valid short or accented English. Rejected ranges continue to be available through literal and lexical search and exact source paging.

Before publishing a vector or returning an excerpt, the component revalidates the complete original source metadata, including exact event/conversation/project IDs, sequence, role, capture status, timestamp, byte count and digest. Query filtering applies the active project and index fingerprint before vector ranking. The existing immutable event contract makes this check stable today. Deletion, revocation, processing grants, and a control epoch are not implemented by this component; enabling those mutations requires the plan's shared gate and worker fencing.

## Background maintenance and publication

Schema 5 persists one `background-index-day-v1` allowance shared by every project, fingerprint, retry and rebuild in one authoritative owner store. It does not aggregate separate stores or machine-wide work. Its anchored, nonoverlapping 24-hour windows cap logical raw work, encoder calls/input bytes, vector publication bytes, metadata inspection and new source jobs. The continuous boot clock and conservative reboot UTC anchors control rollover. Source-job recovery and rebuilding the sidecar retain that store's charges. Schema-5 restore preserves archived accounting before derived rebuild; it does not merge later charges from a live store or supply external budget rollback protection. The [background contract](BACKGROUND-INDEX-BUDGET.md) records exact caps, clock rules, formulas and archive inventory.

The worker preflights source-frontier/cursor/manifest inspection, actual ordered job scheduling, pending-job peek, an initial complete-source seal and each bounded chunk attempt. Scheduling uses an ordered prefix when its canonical source-reference snapshot would exceed 64 KiB. The bounded-page recipe charges `4*(L+1)` logical raw bytes for a page bound `L`, plus explicitly derived seal work. A final page and its fresh full SHA-256 seal are reserved as one composite request before claim, byte access or encoding. The default Apple adapter's two public startup probes consume two calls and 65 input bytes before inference, then contribute their observed vector digest to the fingerprint.

An armed source operation can claim one scoped private read-only connection that strongly retains the main store owner. Its SQL matches all canonical source fields before projecting at most the declared page bound plus one byte. Complete seals traverse pages of at most 4,096 bytes. Original-byte reads, full hashes and inference hold neither main nor sidecar mutex. The live worker can retain one metadata-only initial-seal hint; pause, integrity failure, source/index changes and reopen remove it. Final completion always requires that attempt's fresh full seal.

Publication acquires the sidecar mutex before the main owner. The final owner gate checks live work, adapter quarantine, exact source metadata and private-reader completion, commits submitted state and holds main ownership through bounded SQL/commit on the already-held sidecar. That callback acquires no new sidecar lock and performs no source-byte reading, hashing, inference or blocking observer work. It closes the concurrent-quarantine gap between gate and sidecar commit. Settlement runs after both locks release. A crash between sidecar commit and settlement retains the maximum charge as unknown and preserves the committed offset; a new attempt cannot republish it.

Budget denial preserves cursor and failure attempts, leaves coverage pending and stops the slice before the denied payload/encoder operation. Clock/work refusal and adapter quarantine also fence new publication. A synchronized pause code and authoritative resource snapshot support the native Background indexing status view. If startup probes cannot fit, semantic initialization remains unavailable; original-source retrieval continues and a later capture/open/search trigger can retry when the budget permits. There is no quota override or automatic window renewal on a new project/fingerprint.

Initial and final full seals detect persistent corruption at those reads. Temporary corruption followed by restoration before the final seal can leave an earlier vector derived from changed bytes. A deterministic fixture demonstrates this remaining limitation; exact delivered-range digest checks still guard excerpts. Proving every earlier vector's source bytes requires a separate bounded, resumable validation protocol. No recall or answer-quality claim follows from the current sealing or budget tests.

## Search, fallback, and reproducibility

Queries capture a fixed project ingestion frontier. A coverage snapshot records the scoped events/chunks that are indexed, pending, unsupported, or failed, including holes; it never describes `max(sequence)` alone as complete coverage. Work exceeding an interactive metadata or vector bound is reported with a continuation.

Search combines original-source retrieval with scoped cosine ranks from eligible chunks. Reciprocal rank fusion uses a versioned configuration and deterministic source-sequence/event/range tie breakers. Manual hybrid search defaults to literal plus lexical retrieval; exact literal matches retain priority. Ordinary Send selects `includeLiteral: false` and keeps its bounded any-term lexical formulation, avoiding a new full-archive literal scan on each natural-language prompt. That choice is recorded in the manifest, query-configuration fingerprint, and continuation. One range per event deduplicates overlapping hits, and final excerpts are read from original payloads with their source IDs, digests, offsets, and capture statuses. Similarity and fused scores describe ranking, not factual confidence.

Unindexed, unsupported, failed, or unavailable semantic inputs retain original-source retrieval and paging. With an episode lease, lexical fallback uses the remaining allowance; budget, deadline and source-integrity failures propagate instead of starting fresh work. An empty semantic result cannot establish that an event never happened.

Metered lexical retrieval selects scoped metadata first, reserves conservative load/digest/matching work and loads one complete candidate at a time. Metered literal retrieval traverses bounded UTF-8 pages, hashes the complete source and performs byte matching with state across page boundaries. An unaffordable source remains pending in an explicit continuation before its content is read. Page reads resolve the authoritative scoped metadata before accessing payload, including a reference forged with another project's correct digest. Recent history, delivered-range verification, query encoding, vector/metadata inspection and replay share the caller's lease. Repeated source passes remain charged. Raw-work counters measure declared conservative logical passes and leave physical I/O and internal Foundation comparison work unmeasured.

Read-only context and semantic selection stop on resource-limited raw coverage before implicit range-validation rereads or query encoding. Candidate, result, source, metadata and vector windows remain explicit coverage limits. Browser lexical/literal search uses a standalone read lease through its implicit first page. It can return budget-limited hits with that page suppressed; selecting a hit or requesting Next is a new explicit human action. Source work runs off the main thread, and queued delivery remains fenced by cancellation, supersession and the original deadline. See [READ-EPISODES.md](READ-EPISODES.md).

Optional nil-lease paths remain available for legacy foreground callers and cannot support an episode guarantee. The production background worker always uses its durable daily ledger in addition to per-trigger bounds.

The returned search manifest records query digest, index/encoder/ranking fingerprints, full configuration and its digest, query configuration and result limit, ingestion frontier, published chunk frontier, exact result ranges, and coverage/fallback state. Restarts cannot silently reinterpret an old manifest using newly completed jobs. The sidecar persists each manifest by its digest; `replay(manifestID:projectID:)` retrieves the exact frozen metadata and reads the recorded original ranges again. The first search also persists raw candidate ranges and rank contributions. Vector continuations reference this immutable raw snapshot and never rerun FTS or literal search, preserving initial raw ordering even though FTS5 BM25 statistics can change when the global corpus grows. The continuation checks project, query, lexical formulation, literal mode, excluded IDs, configuration, and both frontiers against its stored snapshot.

Search and replay accept an optional episode lease. Supplying it charges vector bytes, bounded metadata and original-range validation before inspection. Metered raw continuations additionally bind project, query, exclusions, frozen source frontier and originating episode, so replaying them cannot replenish an allowance. The ranking/scanner version compatibility contract still needs tightening before external clients can submit continuations. Main-store schema 6 preserves chat/read origins, their episode journal and schema-5 background accounting, and adds the dormant authority foundation; the derived semantic sidecar remains schema 2. Historical schema 1–5 archive recognition is frozen.

Search continuations also check the supplied episode identity. Manifest replay revalidates frozen ranges under the caller's allowance and can use a new episode; it does not resume the original search. `literalScanBytes` is zero when no literal call occurs, unknown for an unmetered scan, and the literal report's conservative `rawWorkCharged` value for metered scans. Metered literal and lexical coverage records preserve inspected counts, raw charges and continuation state.

Native integration retains a bounded delivery audit and manifest ID alongside the exact request; the larger full manifest lives in the derived sidecar. A restore that excludes that sidecar cannot replay its former manifest IDs. Original payloads, the exact request, and recorded delivery references still permit evidence inspection; derived replay requires a separately retained sidecar/export or a new search. No restored index is silently presented as the original one.

Default worker bounds are 256 new source jobs and 128 computed chunks per scheduling request, with three failure attempts per job. Default search bounds are 4,096 candidate vectors, 1,000 source metadata records, 128 reported unsupported ranges, and at most 100 literal plus 100 lexical candidates. Metadata and vector truncation each expose an explicit continuation; counts describe inspected metadata rather than an unseen whole archive. A pending source can contain committed computed chunks while remaining unavailable for vector serving. Repeated calls to `schedule(projectID:)` coalesce while a worker is running. Pending work resumes on a later capture/open/search scheduling request; the worker does not consume unbounded optional work after one trigger. The daily background budget applies to these triggers. An authenticated manual retry/rebuild interface remains future work.

The index uses a simple bounded exact vector scan rather than an approximate-nearest-neighbor dependency. Its fixed candidate order and continuation make the inspected subset explicit. The 4,096-vector default is an operational bound; it does not establish whole-corpus semantic recall or the 100k-event latency gate. The source seal and configuration are part of index schema 2. Schema-1 derived rows remain isolated under their previous index fingerprint; the original store is unaffected.

Foreground source metadata and sidecar SQL run with SQLite VM progress guards. Their callbacks inspect only the independent episode clock and local cancellation signal, avoiding reentry into the store owner from inside SQLite. Stop or deadline expiry interrupts expensive VM work and restores the prior handler afterward. Background work consumes its own global ledger and uses no foreground lease.

All six checks also pass on a second reopen. The standalone recovery suite was rerun for the episode wave; it exercises the background index lifecycle independently of the GUI coordinator.

Those checks establish component behavior. They do not measure general paraphrase recall, multilingual/code retrieval, answer quality, or superiority over lexical search. The frozen held-out evaluation remains unread and unrun during implementation. Baseline comparisons follow the contracts in [EVALUATION.md](EVALUATION.md).

Installed-index hybrid quality remains unmeasured. Daily background accounting and selected-Qwen recent/evidence token caps are implemented.
