## First working slice

The current working slice provides a native chat interface that connects to the user's running MLX server, preserves accepted history across restart, assembles bounded context, searches original sources, and opens exact source content. The existing AppKit GUI makes Swift plus system SQLite a suitable initial implementation. A separate Python memory daemon is deferred until additional clients justify a service boundary.

The System editor has an explicit Save instructions control. Successful saves retain exact UTF-8 text across restart for future requests in every chat in the local store, including native profiles. Missing historical settings preserve the existing default; a saved empty string removes custom instructions while mandatory history framing remains. Unrelated settings saves retain only the last explicitly saved instruction text. Failed saves do not publish a candidate preference. Instruction text is bounded to 128 KiB and the complete encoded settings file to the archive's 1 MiB ceiling. The private staging file gets `0600` permissions before atomic replacement. This user preference does not enable scoped standing-policy commands or change the dormant managed runtime boundary.

Selected-Qwen Send now records an input receipt before creating its invocation. It links the frozen System text, exact counted request body, accepted human event, complete retained recent messages and every delivered historical range to their original records. Inspection is prepaid under the original episode allowance. A compact checksum and completed work receipt refer to the existing immutable selection evidence; no new source copy or schema change is required. Capture, reopen and archive validation reconstruct that source union and reject mismatched evidence. New captures use admission audit version 3; earlier audit grammars remain supported. This is original-text provenance for the existing `legacyUnbound` answering path. Scoped instruction rendering, current task/policy authority and shared delivery gates remain separate unfinished work.

## Episode and coordinator boundary

Ordinary Send and the synthetic CLI smoke workflow commit the accepted human event and a frozen [episode allowance](EPISODE-BUDGET.md) together before context preparation. One `EpisodeLease` spans recent-source reads, evidence preparation, foreground retrieval, provider discovery, tokenization, calibration, admission retries and answering. Aggregate resources include known model input tokens, output reservations, model calls, HTTP attempts, memory operations and declared source/vector/metadata work. Repeated and cached prompt input still counts; calibration and answering consume the same allowance. A boot-scoped continuous Mach clock enforces the shared deadline across queueing, sleep, preparation and generation.

Work reserves capacity durably before dispatch. Arming charges declared non-output work and holds output headroom before a short serialized handoff starts the operation. Expensive reads, model execution and network waits run outside that handoff's owner lock and transaction. Stop fences new reservations and handoffs; SQLite VM progress callbacks consult an independent clock and local cancellation signal without reentering the owner. Prepared work can release its unused reservation. Armed or submitted work with unknown usage retains its charges and output hold across cancellation, process death, reopen and restore. Late authoritative usage can settle a hold without reopening the episode. Separately established model or usage violations quarantine the stable provider family even when token usage is unavailable. Capacity/capability observations and legacy epoch key changes cannot clear that quarantine; reservation and prepared/already-armed handoff gates check it under the owner mutex.

The coordinator resolves capture status from the authoritative finish receipt. Deadline or budget exhaustion during finalization preserves committed output as partial. During native Stop, Send remains disabled until the owned process and pipe readers finish. Native pipe reads publish short flushed prefixes through bounded `Darwin.read` calls. Delayed timeout and kill closures hold weak references so finished jobs do not keep the store owner alive.

Standalone browser operations and each synthetic evaluation protocol attempt now begin a durable [local read episode](READ-EPISODES.md) before queueing. Search and its automatically selected first page share one allowance. Explicit selection or paging begins a new operation; internal fallback retains its original lease. A globally unique initiator/request-ID pair prevents retries from resetting the deadline or quota. Read origins permit retrieval, source reads and query encoding; they cannot reserve answering or calibration work or acquire an invocation. Store migration and verified archives preserve both origins and their unknown outcomes.

Apple query embeddings and native GGUF/Bonsai input tokens remain unobservable. Development mode records unknown input operations while charging model calls and encoder input bytes where applicable; strict known-input mode skips an uncountable query encoder or rejects native inference. Native output lacks an authoritative token receipt and keeps its reserved output bound held. This work does not establish complete token enforcement for those adapters or exact native admission. Background maintenance has a separate durable global window/work ledger in schema 5, verified at the current checkpoint. The pushed component checkpoint freezes and enforces selected-Qwen recent/evidence limits through independently rendered tokenizer counts.

## Background maintenance boundary

The schema-5 ledger reserves every declared bounded operation before work starts, charges armed work, and preserves uncertain charges after process death. Prepared work releases its unused hold; armed/submitted work becomes unknown without encoder replay. Original limits and start-clock witnesses survive reopen and schema-5 archive restore. A restored store preserves the archived accounting; post-backup charges from a different/current store are not merged, and no external budget antirollback authority is implemented. Current-schema startup requires the background inventory before table creation, while genuine historical schemas reject background tables before migration.

A source reader uses a separate private read-only SQLite handle and validates exact scoped source metadata before bounded payload access. Complete-source seals, UTF-8 pages and chunk/digest/vector publication use a conservative logical-work recipe; the counters do not measure physical disk I/O. A resumed source seals again. Prefixes remain unavailable to vector retrieval until source completion.

The worker holds its sidecar mutex before entering the short main-owner publication gate. The gate rechecks eligibility and quarantine, commits submitted state, and keeps the owner mutex through an already-held sidecar's bounded SQL commit. Source reads, hashing, encoding and observers run outside that callback. This preserves sidecar-to-main lock order and closes concurrent quarantine/terminalization races. Settlement follows separately; a crash after sidecar commit retains the original conservative charge.

Initial/final whole-source hashes cannot prove every intermediate embedding used original bytes if source bytes were temporarily corrupted and restored. Exact excerpt validation still fences delivery, but stronger whole-partition validation remains future work. Installed Apple encoder quality is unmeasured. A deterministic 4 MiB fixture verifies all 4,096 ranges across two windows, including charged startup probes and resume seals.
